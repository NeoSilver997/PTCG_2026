1. Overview & Priority

The function must decide the grid layout (cols × rows) of an image before sending crops to the costly GPU model. Getting this wrong wastes inference time or misses cards entirely. It runs six independent strategies, each casting weighted votes for col/row counts. At the end, the winning vote (if strong enough) overrides an aspect-ratio fallback.

🎯

hint_count (highest priority)

If the user passes --count N, skip all strategies. Find the best cols×rows whose product equals N by minimising cell aspect-ratio error vs the PTCG card ratio.

🗳️

Vote-based fusion

Each strategy adds a float weight to col_votes[N] or row_votes[N]. The N with the highest total weight wins, provided its plausibility filter passes.

🖼️

640px thumbnail

All CV strategies run on a 640×640 max thumbnail. This makes all operations O(1) regardless of original image size and is fast enough (<50 ms).

📐

Aspect-ratio fallback

If all votes are weak (< 1.3), fall back to dividing the image ratio by the PTCG card ratio: cols = round(img_W/H ÷ 0.714).

2. _grid_snap() — the Shared Scoring Engine

Used by SobelX, HueDiff, and SobelY strategies. Given a 1-D profile (mean Sobel or Hue-diff across the image), it scores how well N equal-spaced dividers match the peaks in that profile.

How it works

Step 1 — Compute baseline

Mean of the entire profile = base. Edges above this baseline are significant.

Step 2 — Try each N from 2 to 6

For N cells, the expected divider positions are total × k/N for k=1…N−1.

Step 3 — Sample a ±5% window at each expected position

Take the peak value in that window, subtract the baseline, divide by baseline → normalised peak score per divider.

Step 4 — Average across all dividers

avg_score = mean(per-divider scores). This penalises N values that require edges at positions with no real signal.

Step 5 — Keep the best N

The N with the highest avg_score wins, but only if it exceeds the min_score=0.35 threshold. Otherwise return (0, 0).

score(N) = mean over k=1…N−1 of max(0, (peak_near(k/N) − base) / base )
result = argmax_N score(N) if score(N) ≥ 0.35 else 0

Key insight: A 3-col image has Sobel peaks at 33% and 66% of width. N=3 scores both; N=4 needs 25%/50%/75% — the 75% position has no peak, so avg is lower. N=3 wins naturally.

3. Six Detection Strategies

1
SobelX — vertical edge profile
Targets side-by-side card dividers

Applies a horizontal Sobel filter (dx=1, dy=0) to the grayscale thumbnail. The resulting edge-magnitude image is averaged row-wise to get a 1-D profile across the image width. The profile is smoothed with a box kernel (width ≈ image_width/30) to suppress noise. _grid_snap then finds the best N-divider layout.

Why it works: Two cards sitting side-by-side create a vertical seam — a bright vertical band in the Sobel image — exactly at the card boundary.

→ col_votes Sobel dx=1 smoothed profile
×2.0 × score weight
2
HueDiff — color border transitions
Detects colored card frame edges

Computes the absolute hue difference between adjacent horizontal pixels (wrapping at 0°/180° for hue circularity). Averaged row-wise → 1-D hue-diff profile, smoothed, fed into _grid_snap.

Why it works: PTCG cards have bright-coloured type-specific frames (fire=red, water=blue). Adjacent cards of different types create a sharp hue jump at their boundary, even when the grayscale Sobel shows nothing.

→ col_votes HSV hue channel circular diff
×1.5 × score weight
3
SobelY — horizontal edge profile
Targets stacked card rows

Same as SobelX but with a vertical Sobel filter (dx=0, dy=1), averaged column-wise for a profile across image height. Detects horizontal seams between stacked cards.

Challenge: Single portrait cards also produce strong horizontal edges from artwork — so a midpoint gate is applied (see below).

→ row_votes + midpoint gate Sobel dy=1
×2.0 × score weight
🔒
SobelY Midpoint Gate
Suppresses single-card false positives

After _grid_snap votes for N rows, a midpoint check is run: is there a significant edge at exactly 50% of image height? A real 2-row image always has a card boundary near its midpoint. Artwork edges in a single card almost never produce a peak precisely there.

Rule: n2_score = (peak at 50% − baseline) / baseline. If n2_score < 0.35 → suppress the SobelY vote entirely.

Why NOT applied to SobelX: A 3-col image has no vertical edge at exactly 50% (edges at 33% and 66%), so the same gate would incorrectly suppress legitimate 3-col votes.

rows only — not cols threshold: 0.35 window: ±5% of height
4
AutoCorr — column-mean autocorrelation
Detects periodic card repetition

Takes the column-mean of grayscale (a 1-D signal of how bright each vertical strip is). Mean-subtracts it, then computes full autocorrelation. Searches for the dominant periodicity lag L between width/7 and width/1.5.

Why it works: Multiple identical cards create a repeating pattern with period ≈ card width. N = round(image\_width / lag) gives the column count.

Minimum autocorrelation threshold: r = 0.25. Weaker periodic signals are ignored.

→ col_votes min r=0.25 lag range: W/7 … W/1.5
×1.5 × r weight
5
Contour — card-shaped blob detection
Works when background is visible

Thresholds the HSV saturation channel (sat > 30) to find colourful regions, then applies a large morphological close to merge each card into one blob. Contours are filtered by area (≥ 4% of image) and bounding-box aspect ratio (within ±30% of 0.714).

Card centre points are clustered into column and row bins using _unique_bins() with a 10% gap threshold.

→ col_votes + row_votes saturation threshold ratio filter ±30%
3.0 flat highest confidence
6
YOLOv8n — object bounding boxes
General object detector repurposed for card layout

Runs YOLOv8n (COCO 80-class, 6.2 MB) on the 640px thumbnail at low confidence (conf=0.08, iou=0.3). Class labels are ignored — only bounding box geometry matters. Boxes ≥ 5% area and with W/H ratio within ±30% of 0.714 are accepted as "card-like".

Accepted box centres are clustered with _unique_bins(gap=15%) to vote for cols and rows.

The model is cached as a module-level singleton so it loads only once.

→ col_votes + row_votes conf=0.08 area ≥ 5% ratio ±30%
1.5 flat (below contour=3.0)
FB
Aspect-ratio fallback
Last resort — no CV evidence needed

Divides the image's W/H ratio by the PTCG card ratio (0.714) and rounds.
Landscape (W > H·0.85): cols = round(img_W/H ÷ 0.714), then row = round(H / expected_H).
Portrait: rows = round(0.714 / img_W/H), cols = 1.

Used when best vote score < 1.3 threshold.

cols + rows pure geometry

4. Plausibility Filter & Vote Aggregation

After all strategies vote, impossible grid configurations are pruned before the winner is picked.

Column plausibility (col_votes)

cell_W/H = iw / N / ih
Accept N if: 0.40 ≤ cell_W/H ≤ 1.50
# Too narrow (< 0.40): more cols than physically fit in image width

Example: a 1920×1080 landscape photo with N=3 cols gives cell W/H = 640/3/360 ≈ 0.59 — inside range ✓.
N=8 would give 0.22 — rejected.

Row plausibility (row_votes) — stricter

cell_H/W = ih / N / iw
Accept N if: 1.0 ≤ cell_H/W ≤ 1.50
# Minimum 1.0: each row strip must be taller than wide (portrait card) # A phone-photo (H/W=1.78) with N=2 rows → cell_H/W = 0.89 → rejected!

This is the key fix for single portrait cards: a 1080×1920 image (H/W=1.78) with 2 stacked cards would need H/W≈2.80, but the image only has 1.78. N=2 sub-cell H/W = 0.89 < 1.0 → filtered out automatically.

Winner selection

best_col = argmax(valid_col_votes)
cols = best_col if valid_col_votes[best_col] ≥ 1.3 else ratio_fallback_cols
# Same for rows
# Final cap: if cols×rows > 12, fall back to ratio estimate
